## 외력 주입 — ForceAccumulator 구현 규칙 (가영, 팀 리뷰용)

- 각 모듈은 `acc.add(body_id, force_w, torque_w=None, point_w=None)`로 외력을 전달합니다.
- 힘은 N, 토크는 N·m, 작용점은 m이며 모두 월드 좌표입니다. 몸체 ID는 월드(0)를 제외합니다.
- `point_w`가 없으면 힘은 몸체 무게중심에 작용합니다. 있으면
  `토크 = torque_w + (point_w - data.xipos[body_id]) × force_w`로 합산합니다.
- 한 스텝 순서: `reset → 모듈별 add → apply → mj_step`.
- 첫 스텝 및 자세를 직접 바꾼 뒤에는 `mj_forward` 등으로 현재 무게중심 위치를 갱신합니다.
  모듈이 위치 기반 힘을 계산하기 전에도 파생 위치가 현재 `qpos`와 일치해야 합니다.
  조립 테스트 루프는 매 스텝 시작에 `mj_forward`를 호출해 이를 보장합니다.
- `reset()`은 누적 기록만 비웁니다. `apply()`가 `xfrc_applied`를 현재 합산값으로 교체하고
  `qfrc_applied`를 0으로 비웁니다. 힘이 없으면 두 배열 모두 0이 됩니다.
- 두 외력 배열에는 `sim/forces.py`만 씁니다. 반복 `apply()`는 힘을 중복 누적하지 않습니다.
- MuJoCo 내장 중력·접촉·tendon 스프링 힘은 엔진이 처리하므로 같은 힘을 다시 `add()`하지 않습니다.

## 세계 조립 — 구현 규칙 (가영, 팀 리뷰용)

- `build_world()`는 모든 모듈의 `build(spec)` → `spec.compile()` → 모든 모듈의
  `bind(model)` 순서로 조립합니다. 이후 `MjData`를 만들고 `mj_forward`로 초기 상태를 갱신합니다.
- 반환된 `World`의 `model`, `data`, `parts`, `acc`를 단계 연결 담당자가 사용합니다.
  스텝 순서와 단계 전환 구현은 `phase_manager.py`의 담당 범위입니다.
- 기본 조립 순서는 물 → 로봇 → 사람 → 구명환 → 줄입니다. 고정 연결 구명환은 사람의 build 뒤에 생성합니다.
  연결된 줄을 조립할 때는 양쪽 site가 먼저 생성되어 있어야 합니다. 이는 단계 담당의 스텝 순서와 별개입니다.
  조립 테스트는 `parts` 인자로 대체 모듈을 넣을 수 있습니다.
- timestep·중력·integrator·내장 유체 옵션은 `world.py`에서만 설정합니다.
  모듈이 이를 변경하거나 timestep이 모듈의 `REQUIRES['max_dt']`보다 크면 조립을 중단합니다.
- 미확정 config 값은 자동으로 채우지 않습니다. 실험용 인자를 명시해서 실행하며 계약 확정값과 구분합니다.
- MjSpec 사용법: [MuJoCo 공식 Python 문서](https://mujoco.readthedocs.io/en/stable/python.html#model-editing).

## 사람·줄 설정 — 가영의 독립 구현용 초안 (팀 합의 전)

이 절은 위 문서의 확정 규칙과 구분되는 제안입니다. `human.py`에는 부위별 형상을 가진 사람 강체를 구현했고,
`tether.py`에는 tendon 스프링과 인장 감쇠 보정을 구현했습니다. 이름은 공유 예정이며 수치는 실측·문헌 근거 없이
단순 모델 구현을 시작하기 위해 정한 시험값입니다. 사람 강체의 크기·질량·자유낙하는 검사했으며,
실제 인체의 물리적 타당성과 물·로봇·줄 통합 안정성은 아직 검증하지 않았습니다.

| 구분 | 설정 | 초안과 의미 |
| --- | --- | --- |
| 사람 이름 | `Names.HUMAN_BODY/FREE/GEOM/TOW_SITE` | `human` / `human_free` / `human_geom` / `human_tow_point` |
| 줄 이름 | `Names.TETHER_TENDON` | `tow_tendon` |
| 사람 형태 | `Human.SHAPE` | 기본 `humanoid`: mesh 몸통·타원형 머리·분절 팔다리·얼굴을 한 body에 고정 |
| 기존 상자 크기 | `Human.LENGTH/WIDTH/HEIGHT` | `Human(shape='box')`에서만 사용하는 1.7 × 0.4 × 0.2 m |
| 질량·무게중심 | `Human.MASS` | 총 70kg을 부위별 배분, 기본 모드의 무게중심·관성은 MuJoCo가 형상으로 계산 |
| 사람 로컬 축 | 구현 제안 | +x 머리 쪽, +y 왼쪽, +z 몸의 앞면. 초기 월드 자세는 미정 |
| 줄 기준 길이 | `Tether.REST_LENGTH` | 2 m, 초기 두 연결점 거리와는 별개 |
| 강성·감쇠 | `Tether.STIFFNESS/DAMPING` | 100 N/m, 10 N·s/m, 검증 전 시험값 |

미확정 값은 `None`으로 유지합니다. 후속 구현에서 필요한 값은 명시적으로 검사하며,
0이나 False로 자동 해석하지 않습니다.

- `Human.TOW_POINT_B`와 `Names.HUMAN_TOW_SITE`: 이전 직접 연결 초안의 예약 항목으로 사용하지 않습니다.
  실제 로프 끝은 구명환의 `Names.LIFEBUOY_TOW_SITE`에 연결합니다.
- `Tether.ATTACH_ON_START`: 연결 시점 — 동경·태수와 확인.
- `Tether.BREAK_FORCE`: 끊김 모델 도입 여부와 기준 — 후속 범위 결정 필요.
- 사람의 부력·물 저항은 `Water(floating_bodies=[Names.HUMAN_BODY])`로 시험 적용하며, 물성·인계 방식은 미현과 확인.
- `Groups` 번호 및 `contype`·`conaffinity` 충돌 규칙 — 공통 합의가 필요해 이번에는 유지.
- 로봇 쪽 연결점은 기존 합의 이름 `Names.TOW_POINT_SITE` (`tow_point`)를 사용하며 위치는 로봇 담당과 확인.

기본 사람 구현은 자유 관절 하나와 단면 mesh 몸통·타원형 머리·분절 팔다리·손발·얼굴로 구성합니다.
각 geom의 질량은 `Human.MASS_FRACTIONS` 비율로 나누며 body에 질량을 중복 지정하지 않습니다.
관절이 없는 한 body의 형상이므로 팔다리는 서로 움직이지 않습니다.
기존 box 모드만 body에 질량·관성을 지정하고 `Human.COM`을 사용합니다.
`Human(position=(0, 0, 1))`의 기본 배치는 독립 시험용이며 실제 구조 장면의 배치 확정이 아닙니다.
충돌 합의 전에는 사람 geom의 `contype=0`, `conaffinity=0`으로 접촉을 끕니다.
그룹이 미정이면 로컬 시험에서만 그룹 0을 사용하며 `config.Groups`의 합의값은 변경하지 않습니다.
`bind()`는 몸체·자유 관절·geom의 ID를 저장하고, `add_forces()`는 현재 아무 외력도 추가하지 않습니다.
사람의 부력·저항은 Water에서 명시적으로 선택하며, 실제 로프는 구명환 연결점을 사용합니다.

## 구명환 — 형상·로프 연결점 시험 구현 (가영)

- 구조 요구: 배 선미의 `tow_point` → 로프 → 구명환. 사람은 몸통을 환 안에 넣고 팔을 밖으로 둡니다.
- `sim/lifebuoy.py`는 yz 평면의 원을 캡슐 12개로 근사한 하나의 강체를 만듭니다.
  가운데 구멍은 실제로 열려 있으며, 물리 형상도 하나의 볼록 덩어리로 합치지 않습니다.
- `config.Lifebuoy`의 시험값: 중심선 반지름 0.325m, 튜브 반지름 0.075m, 총질량 2kg.
  바깥 지름 약 0.8m, 내부 개구 폭은 다각형 근사로 약 0.478m입니다. 실측 제품 사양은 아닙니다.
- 기본 고정 연결은 사람의 자식 body로 구현합니다. 구명환의 추가 관절은 없고, 전체 자유도는 6입니다.
  사람 질량 70kg은 유지하며 구명환 질량 2kg만 추가해 총 72kg입니다.
- 환 중심은 사람 로컬 좌표 `(0.35, 0, 0)`에 둡니다. 로프 site 이름은 `lifebuoy_tow_point`,
  환 로컬 좌표는 `(0.075, 0.325, 0)`인 임시 표면 위치입니다. 실제 묶음 위치는 조정 대상입니다.
- `Lifebuoy(attached=False)`로 구명환만의 자유 관절 시험도 가능합니다.
- 접촉은 아직 없습니다. 부력은 Water의 명시적 시험 대상으로 선택하고, 로프는 실제 움직이는 배 연결 시험까지 수행합니다.
  양팔이 환 밖에 나오는 형상을 만들었으나 팔로 걸쳐 지지되는 물리는 미구현입니다.
  고정 연결은 기하·힘 전달 시험을 위한 근사입니다.
- 형상 참고: [MuJoCo geom 공식 문서](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-geom).

사람 형상 상세값과 질량 비율은 모두 시험용 가정값입니다. 몸통/머리/양팔/양다리의 질량 비율은
50% / 8% / 각 6% / 각 15%이며 합계는 100%입니다. 이는 검증된 인체 분절 자료가 아닙니다.
기본 배치에서 몸통은 구명환의 구멍 안에, 양팔은 환보다 머리 쪽에 두며 모든 사람 geom과 환 사이의
비침투를 거리 검사로 확인합니다. 기존 사람 이름 `human_geom`은 기본 모드에서 몸통 geom을 가리킵니다.
`Human.geom_ids`는 사람 body에 속한 모든 형상 이름→ID를 저장하고, `geom_id`는 기존처럼 대표 몸통 ID를 제공합니다.

## 줄 — 인장 전용 tendon 시험 구현 (가영)

- 실제 연결 대상은 `Names.TOW_POINT_SITE` → `Names.LIFEBUOY_TOW_SITE`입니다.
  `build` 전에 두 site를 생성하고, `bind`에서 tendon·site·몸체 ID를 저장합니다.
- 실제 연결 단계가 미완성이므로 기본 세계는 `Tether(enabled=False)`로 명시합니다.
  이는 `ATTACH_ON_START=None`을 False로 해석한 것이 아닙니다. 시험에서만 `enabled=True`를 사용합니다.
  `enabled`는 조립 여부이고 `attached`는 실행 중 연결 여부입니다. 자동 연결은 아래 전체 시나리오에서 시험합니다.
- MuJoCo의 `springlength=(0, REST_LENGTH)`로 기준 길이 이하의 스프링 힘을 없앱니다.
  엔진이 스프링을 계산하며 같은 스프링 힘을 ForceAccumulator에 중복 추가하지 않습니다.
- 내장 tendon damping은 0입니다. `add_forces`에서 감쇠 보정만 계산합니다.
  늘어난 줄의 총장력은 `T=max(0, k*(L-L0)+c*Ldot)`, 느슨한 줄은 `T=0`입니다.
  `Ldot>0`은 늘어남이며, 엔진 스프링 장력 `Ts`에 대한 차이 `T-Ts`만 양 끝 작용점에 전달합니다.
  빠르게 줄어들 때 보정은 스프링을 상쇄할 수 있으나 전체 로프는 밀어내지 않습니다.
- `tension(model, data)`는 현재 총장력[N]을 제공합니다. 위치·속도 정보를 갱신한 후 읽습니다.
- 월드 고정점에는 외력을 쓰지 않고 움직이는 양쪽 몸체에는 작용·반작용을 전달합니다.
- 끊김, 로프 자체 질량, 중간 장애물 감김, 실제 느슨한 줄의 처짐 물리는 미구현입니다.
  비교 뷰어는 아래 표시용 곡선으로 남는 길이를 표현합니다.
- [MuJoCo springlength·감쇠 설명](https://mujoco.readthedocs.io/en/stable/XMLreference.html#tendon-spatial-springlength)을 참고했습니다.

`view_tether`의 기본 화면은 중력을 끈 비교 실험이며 실험값은 `build_world(gravity=0)`으로 명시합니다.
공통 `Physics.GRAVITY`와 로프 강성·감쇠는 바꾸지 않습니다. 느슨한 배치에서 정지하는 장면과,
1m 늘어난 배치로 리셋·일시정지한 뒤 놓았을 때 당겨지는 장면을 비교합니다.
길이·늘어남·장력·이동 거리 HUD, 상태별 색상, 힘 방향 화살표와 시작 위치 선은 시연용 표시입니다.
이 데모의 배치 리셋·일시정지·반복은 실제 단계 전환 정책이 아닙니다.

`rope_visual.rope_curve()`는 끝점 거리 d가 기준 길이 L0보다 짧으면, 구간 길이의 합이 L0가 되는
표시용 S 곡선을 만듭니다. d>=L0이면 표시 길이는 d인 직선입니다. 따라서 표시 길이는 항상
`max(d, L0)`이며 느슨함을 로프 자체의 단축으로 표현하지 않습니다.
끝점이 일치하는 경우에는 길이를 가진 닫힌 고리를 표시합니다.
곡선은 기본 64개 구간이고 양 끝점은 실제 site 위치와 일치합니다. 기본 tendon 직선은 뷰어에서
투명하게 처리하여 중복 표시하지 않습니다. 모델의 기준 길이·강성·장력 계산은 변경하지 않습니다.
장력 색상과 별도로 곡선 여부는 남는 길이로 정합니다. 장력이 0이어도 감쇠 보정으로 아직 늘어난
상태일 수 있으므로 '장력 0이면 무조건 곡선'으로 처리하지 않습니다.

## 배·구명환 통합 시험 (2026-11-13)

- `Robot`은 `Hull` 계약의 box·질량·COM·관성과 `Thruster`의 좌우 site를 생성합니다.
  질량은 body inertial에 한 번만 지정합니다. 충돌은 공통 합의 전이라 비활성입니다.
- `set_command(forward, steering)`은 각각 계약 범위의 유한한 입력을 받으며,
  좌=전진−조향 / 우=전진+조향을 혼합 후 포화합니다. 전진·후진 최대값은 각각의 계약값을 사용합니다.
- 추력은 몸체 +x에서 월드로 변환하고 실제 추진기 site에 `acc.add`합니다.
  `WaterAPI.USE_IN_WEEK1=False`에 따라 수면 연동은 하지 않습니다.
- 선미 연결점 위치는 미합의이므로 `Robot(tow_point_b=...)`에 명시한 경우에만 생성합니다.
  `view_towing`의 선미 중앙 좌표는 시험값이며 공유 계약 확정이 아닙니다.
- `view_towing --dry`는 중력 0에서 실제 움직이는 배와 구명환을 tendon으로 연결합니다.
  초기 로프는 늘어나 있고 추력도 가해집니다. 1,000스텝 동안 견인·유한 상태를 검사합니다.
  추력 0일 때 양쪽 이동 및 총 선운동량 보존, 줄이 없을 때 사람 정지를 별도로 검사합니다.
- 기본 `view_towing`은 처음부터 로프가 연결된 수상 견인 시험입니다. 접근·자동 연결·견인 전환은 아래 전체 시나리오에서 실행합니다.

## 사람 외형 개선 (2026-11-13)

## 부력·물 저항·수상 견인 시험 (2026-11-13)

- `Water.bind`는 boat의 hull 크기를 모델에서 읽고 `VOXEL_RES`로 복셀화합니다.
  선체 질량·관성을 수정하지 않으며 부가질량 활성화는 아직 지원하지 않습니다.
- 부력은 `rho * |model.opt.gravity| * 잠긴 부피`입니다. 각 복셀의 부분 침수와
  잠긴 부분의 평균 중심을 사용합니다. 직립 box는 해석적 부력·부력 중심과 일치합니다.
  회전한 복셀은 수직 투영 높이를 사용한 근사이므로 유체 표면을 정확히 절단하는 해법은 아닙니다.
- 부력·이동 저항·회전 저항은 모두 ForceAccumulator를 통해 주입합니다.
  물 밖에서는 세 항 모두 0입니다. 이동 저항은 월드 해류를 뺀 뒤 body 좌표에서 계산합니다.
  저항은 선형+속도제곱 항이고, 선체 heave·roll·pitch 선형 감쇠는 기존 계약 감쇠비를 사용합니다.
- 기본 Water는 선체만 처리합니다. 사람은 `floating_bodies=[Names.HUMAN_BODY]`로 선택합니다.
  `buoyancy.body_voxels`는 사람과 고정 자식 구명환의 형상 합집합을 적분해 겹친 부피를 한 번만 셉니다.
  몸통 mesh는 볼록 외피, 타원체·캡슐은 해당 형상 내부를 샘플링합니다. 얼굴 외형도 부피에 포함합니다.
  부모·자식을 중복 부력 대상으로 지정하면 조립 오류로 알립니다.
- 사람 물성은 `RescueWater`의 검증 전 시험값입니다. 인체 밀도·의복·호흡·침수·유체 상호작용은
  재현하지 않습니다. 사람과 환은 계속 고정 연결이고, 물속 자세는 강체 회전 결과입니다.
- 수면 표시는 선택적 반투명 평면이고 접촉력이 없습니다. 파도는 수면 높이만 변경하며
  수면 표시 변형·물 입자 속도는 미구현입니다. 이번 검증 범위는 잔잔한 물입니다.
- `view_towing`은 줄이 느슨한 상태에서 시작하고 전진 0.2로 연속 견인합니다.
  선미 연결점 `(-Hull.LENGTH/2, 0, -0.08)`은 시험 인자이며 공유 합의값은 아닙니다.
  GUI는 연속 실행, headless는 리셋 없이 10초(5,000스텝)를 확인합니다.
- 검증: 해석적 box 부력·흘수, 물 밖 외력 0, 중력 override, 실제 roll/pitch 복원,
  해류 상대 저항·방향 변환·에너지 소산, 부피 합집합·자세 독립성, 사람 정지 부유·10초 수상 견인.

## 목표 접근·정지 제어 첫 단계 (2026-11-13)

- `PhaseManager(world, robot, target_xy, target_heading=...)`는 선체 원점의 월드 xy와 yaw를 목표로 합니다.
  `step()`은 현재 상태 갱신 → 명령 갱신 → acc.reset → parts 순서 add_forces → apply → mj_step →
  상태 갱신을 수행합니다. parts 순서는 world 조립 순서를 따르며 시험은 Water → Robot입니다.
- 제어 갱신은 Sim.CONTROL_HZ, 물리 스텝은 Sim.TIMESTEP을 유지합니다.
  월드 리셋으로 시각이 뒤로 가면 제어 타이머·도착 판정을 초기화합니다.
- 접근은 목표 수평 속도와 현재 수평 속도 차이로 힘을 구합니다. 필요한 힘의 방향으로 조향하며
  제동에 역추력도 사용합니다. 정·역추력 최대값이 다르므로, 필요한 힘·yaw 토크를 좌우 힘으로
  분배한 뒤 정규화 명령으로 변환합니다. 추가 힘을 직접 주입하지 않고 Robot.set_command만 호출합니다.
- APPROACH → SETTLE → ARRIVED를 구현했습니다. 5cm 안에서 방향 정렬을 시작하며,
  위치 20cm·속도 0.05m/s·방향 8도·yaw 속도 0.03rad/s 조건을 1초 유지해야 도착입니다.
  모든 계수·허용 오차는 ApproachSettings의 시험값이며 확정 구조 시나리오 계약은 아닙니다.
- ARRIVED에서도 정지 보정을 계속합니다. 조건을 벗어나면 SETTLE, 거리 21cm를 넘으면
  APPROACH로 돌아갑니다. 현재 차동 추진으로 임의 방향 해류에서 정밀 위치 유지를 보장하지 않습니다.
- `view_approach`는 사람·로프 없이 배만 접근시키는 독립 시연입니다.
  출발 위치·방향, 목표 위치·도착 방향을 지정할 수 있습니다. CLI 각도는 도, Python API는 rad입니다.
- 검증: 대각선·반대 방향 출발·뒤쪽 목표·초기 속도가 있는 접근, 역추력 제동,
  도착 후 정지 유지, 도착 시 제자리 회전의 질량 이동 방지, 도착 체류 시간, 월드 리셋과 재접근,
  제어 갱신 주기, 잘못된 목표·설정 거부를 확인합니다.
- PhaseManager 단독은 배의 위치·방향 제어를 담당합니다. 사람 접근과 로프 연결·견인 전환은
  아래 RescueApproach·RescueMission에서 이를 조합합니다. 실제 접촉 판정은 후속 작업이며 전체 시나리오 Watchdog는 아래 절에서 적용합니다.

## 구명환 연결 위치 접근 (2026-11-13)

- `RescueApproach`는 기존 PhaseManager를 사용하며 TRANSIT → ALIGN_STERN → BACK_IN → READY를 관리합니다.
  물리 스텝은 PhaseManager.step에서 한 번만 실행합니다. 사람·배 위치를 직접 보정하거나 리셋하지 않습니다.
- 목표는 현재 `lifebuoy_tow_point`의 월드 xy와 지정한 견인 방향입니다.
  선미 site의 로컬 오프셋과 현재 roll/pitch를 반영해 배 원점의 목표를 계산합니다.
  큰 기울기·전복 상황에서의 연결은 이번 범위에 포함하지 않습니다.
- 현재 형상의 시험용 원호 경유점(반지름 4.5m, 최대 각 간격 30도)을 따라 이동하고,
  선미 간격 3m에서 최종 방향을 정렬한 뒤 최대 목표 속도 0.2m/s로 후진 접근합니다.
  초기 선체 원점과 구명환 site 거리는 경로 반지름 이상이어야 합니다.
- READY에는 PhaseManager의 도착 조건, 실제 3D site 간격 0.7m±0.15m,
  site 상대속도 0.06m/s 이하가 필요합니다. 추가로 1초 동안 조건을 유지합니다.
  조건이 깨지면 BACK_IN으로 돌아가며, 대기 중에도 작은 위치·속도 보정을 계속합니다.
- 선체 hull과 사람·구명환의 모든 geom 사이 거리를 제어 주기로 검사합니다.
  0.1m보다 작으면 추진 명령을 0으로 바꾸고 오류로 시험을 중단합니다.
  접촉 반응·연속 충돌 검출을 대신하는 기능은 아닙니다.
- `view_rescue --approach-only`는 부력·물 저항이 켜진 잔잔한 물에서 실행하며 tendon은 생성하지 않습니다.
  READY 뒤 5초 대기 유지, 정면·반대편 출발·다른 견인 방향의 최소 형상 간격을 검사합니다.
  로프 미연결 상태에서 사람 운동이 독립 부유 계산과 일치하는지도 확인합니다.
- 월드가 초기 출발 배치로 리셋되면 경로·준비 판정을 초기화합니다.
  임의의 근접 위치에서 새 경로를 계획하는 기능은 아직 없습니다.
- 실제 접촉 판정은 후속 작업입니다. 동적 연결·견인 전환·Watchdog는 아래 전체 시나리오에서 시험합니다.

## 실행 중 로프 연결·견인 전환 (2026-11-13)

- `Tether(enabled=True, attached=False)`는 tendon을 조립하되 초기 스프링 계수를 0으로 둡니다.
  `enabled=False`는 기존처럼 tendon을 생성하지 않습니다. enabled=True의 attached 생략 기본값은 True로
  기존 독립 시험의 처음부터 연결된 동작을 유지합니다. ATTACH_ON_START 미합의 값은 변경하지 않습니다.
- `attach(model)`/`detach(model)`는 해당 모델에 bind된 tendon의 스프링 계수를 복원/0으로 바꿉니다.
  감쇠 보정도 detached에서는 0입니다. 위치·속도·기준 길이·질량은 변경하지 않습니다.
  연결/해제 뒤 파생 힘을 읽기 전에는 mj_forward가 필요하며 정상 스텝 루프에서 이를 수행합니다.
- `mj_resetData`는 모델의 스프링 계수를 복원하지 않으므로 `Tether.reset(model)`을 함께 호출합니다.
  `RescueMission.reset`은 이를 처리하고 접근 경로·연결 시간·완료 체류 시간을 초기화합니다.
- `RescueMission`은 APPROACH → ATTACH → TOW → COMPLETE를 관리합니다.
  READY 이후에도 현재 위치·방향·속도·3D 연결점 간격·상대속도를 다시 검사해 연결하며,
  조건이 깨졌으면 미연결 상태를 유지하고 접근 제어로 돌아갑니다.
- 연결은 기준 길이 2m보다 짧은 약 0.7m 간격에서 수행합니다. 따라서 초기 장력은 0이며
  배가 전진해 느슨함을 해소한 뒤 실제 힘이 사람·구명환에 전달됩니다. 공간 배치를 리셋하지 않습니다.
- 견인 목적지는 연결 순간 선체 원점에서 견인 방향으로 6m, 목표 속도 상한은 0.4m/s인 시험값입니다.
  기존 PhaseManager를 재사용하되 목표 위치 오차 20cm에서 정렬을 시작하고 재접근 기준은 50cm로 둡니다.
  로프가 연결된 상태에서 마지막 수 cm를 추적하며 선미가 크게 회전하는 상황을 줄입니다.
- COMPLETE 조건은 배 도착, 사람 진행 2m 이상, 사람 수평 속도 0.05m/s 이하, 장력 10N 이하를
  1초 동안 만족하는 것입니다. 이후에도 정지 보정을 수행하고 조건이 깨지면 TOW로 돌아갑니다.
  headless는 5초 추가 유지를 검사합니다. 모든 값은 RescueMissionSettings의 시험값입니다.
- 기존 `build_rescue_demo`는 로프 없는 접근 단독 API로 유지합니다. `build_rescue_mission`이
  처음에는 미연결인 로프를 포함한 세계와 전체 제어를 생성합니다. CLI 기본은 전체 시나리오이고
  --approach-only로 기존 시험을 선택합니다.
- GUI는 연결 여부·장력·사람 진행 거리를 표시합니다. 미연결 로프는 숨기고 연결 후에는
  기존 길이 보존 곡선을 사용하며 이는 물리적 처짐·접촉 모델이 아닙니다.
- 검증은 초기 미연결 native 스프링·감쇠 힘 0, 연결/해제의 실제 가속도, 위치·속도·기준 길이 보존,
  재연결의 비중복, 모델 리셋 복원, 오래된 도착 플래그만으로 연결하지 않는 조건 검사,
  두 견인 방향의 연속 접근·연결·견인·완료 후 정지 유지와 형상 간격을 포함합니다.
- 실제 접촉·후크와 로프 끊김·추론 응답 지연 감시는 후속 작업입니다. 전복·수치 오류·시뮬레이션 시간 감시는 아래 Watchdog에서 처리합니다.

## 실패 감지와 중단 (2026-11-13)

- `MissionWatchdog`는 전체 RescueMission에 기본 적용하며 추론 응답의 wall-clock 지연은 감시하지 않습니다.
  WatchdogSettings의 시험 기본값은 접근 150초·연결 5초·견인 100초·전체 240초, roll/pitch 60도입니다.
  시간은 `data.time` 기준입니다. 완료 후에는 전체 제한을 적용하지 않지만 수치·경고·전복 검사는 계속합니다.
  공유 미확정 Capsize 계약값은 변경하지 않습니다.
- 단계 변경 시 단계 제한 시각은 갱신하지만 전체 제한 시작 시각은 유지합니다.
  실패 기록은 코드·원래 단계·발생 시각·메시지이며 최초 기록을 명시적 reset 전까지 유지합니다.
- 미분 상태·힘·파생 위치 등에 NaN/무한대, 잘못된 선체 quaternion, MuJoCo warning,
  시각 역행 또는 제한 시간 초과를 검사합니다. 전복은 mj_forward 전에 qpos quaternion에서 판정합니다.
  정상 초기 배치로의 mj_resetData는 건강한 실행에서 기존처럼 감지해 제어·감시 시계를 초기화합니다.
- RescueMission.step은 물리 실행 전후 검사합니다. 실패 시 FAILED로 전환하고 Robot 명령을 0으로,
  ForceAccumulator.reset/apply로 외력을 0으로 만듭니다. 이후 step은 False이며 추가 물리를 진행하지 않습니다.
  로프를 자동 해제하거나 실제 qpos/qvel을 초기화하지 않습니다. 기존 RuntimeError도 CONTROL_ERROR로 기록합니다.
- GUI는 별도 MjData에 정상 상태를 복사해 표시합니다. 수치 실패는 마지막 유효 자세를 표시하고,
  전복·시간 초과처럼 자세가 유효한 실패는 그 시점 자세를 표시합니다. 실패 후 HUD 수치는 마지막 정상 기록이며
  중단 코드·원래 단계·발생 시각을 함께 표시합니다. 실제 오류 상태는 원인 확인을 위해 유지합니다.
- FAILED는 mj_resetData만으로 해제되지 않습니다. mj_resetData 후 mission.reset을 명시적으로 호출해야 합니다.
  이때 실패·단계 시계·경로·tendon 초기 연결 상태를 함께 복원합니다.
- headless는 실패 코드·단계·시각·메시지를 출력하고 종료 코드 1을 반환합니다.
  --failure-demo timeout/capsize/nonfinite/warning은 명시적 오류 주입 시험입니다.
  --approach-only 독립 시험에는 이 Watchdog를 적용하지 않습니다.
- 검증: 단계·전체 제한 시계, 순수 roll/pitch와 역전 자세, 정상 yaw의 비전복,
  NaN/무한대·무효 quaternion, 전후 검사, MuJoCo 경고, 실패 후 시간·자세 동결과 외력/명령 0,
  유효한 실패 렌더 데이터, 명시적 재시작, CLI 비정상 종료, 정상 전체 구조 시나리오 회귀를 포함합니다.

## 담당 범위 정정: 사람·구명환 받기 연결 (2026-11-13)

- 배의 구명환 탑재·전달·운항은 배 담당 범위입니다. 가영의 구현은 로프 → 독립 구명환 → 손의
  잡기 연결 → 사람의 힘 전달과 잡기·놓기 조건입니다. 이번 변경은 Robot과 배 시나리오 제어를 수정하지 않습니다.
- 기존 고정 연결 구명환과 전체 배 시연은 초기 견인 근사로 남겨 둡니다. 새 전달 흐름은
  `Human(grip_sites=True)`, `Lifebuoy(attached=False, grip_sites=True)`, `HumanGrasp`로 조립합니다.
  사람과 환은 각각 자유 관절을 갖고 별도 월드 자식이며 질량은 70kg·2kg을 유지합니다.
- 로프는 처음부터 배 쪽 `tow_point`와 환의 `lifebuoy_tow_point`에 연결된 상태입니다.
  받기·놓기는 Tether 연결 상태를 바꾸지 않고 사람과 환의 equality만 켜고 끕니다.

| 인터페이스 | 소유·역할 |
| --- | --- |
| Names.TOW_POINT_SITE | 배 담당이 만드는 로프 연결점. 독립 시험은 외력 제어 질점으로 대체 |
| Names.LIFEBUOY_TOW_SITE | 구명환의 로프 연결점 |
| Names.HUMAN_GRIP_L_SITE / HUMAN_GRIP_R_SITE | 사람 손 표면의 잡기 기준점 |
| Names.LIFEBUOY_GRIP_L_SITE / LIFEBUOY_GRIP_R_SITE | 손이 잡는 환 테두리의 기준점; 로프 연결점과 별개 |
| delivery_ready: bool | 배/단계 담당이 탑재 고정을 해제하고 수령 가능 상태로 전달했다는 신호; True만으로 강제 연결하지 않음 |
| HumanGrasp.try_grab(model, data, delivery_ready=...) | 실제 거리·속도 조건 확인 후 연결 성공 여부 반환 |
| HumanGrasp.release(model, data) | 손↔환 연결만 해제; 위치·속도·로프 상태는 유지 |

- try_grab 성공 반환을 받으면 배 담당이 전달 장치의 환 위치 제어를 끝내고 로프 견인으로 넘깁니다.
  잡기 모듈은 배의 탑재 제약·전달 장치를 직접 조작하지 않습니다.
- 잡기 조건은 site 간격 ≤0.08m, 상대 선속도 ≤0.1m/s, 상대 각속도 ≤0.5rad/s인 시험값입니다.
  현재는 한 손(left/right)을 선택하며 양손·손가락·접촉 동작은 구현하지 않습니다.
- 비활성 body weld를 조립하고 잡는 순간 `eq_data`의 상대 위치·quaternion을 갱신한 뒤
  `data.eq_active`를 켭니다. 초기 자세로 강제 복원하지 않으며 qpos/qvel/시간을 직접 바꾸지 않습니다.
  연결은 엔진의 부드러운 고정 제약 근사라 하중 아래 작은 상대 오차가 발생할 수 있습니다.
  제약력은 엔진이 처리하므로 ForceAccumulator에 같은 힘을 추가하지 않습니다.
- try_grab 전과 연결/해제 후 힘을 읽기 전에는 mj_forward로 파생 상태를 갱신합니다.
  mj_resetData 뒤 HumanGrasp.reset은 활성 상태와 모델의 기준 상대 자세를 함께 초기화합니다.
- `view_grasp`는 배 없이 전달 입력·잡기·견인·놓기를 확인하는 기본 중력 0 시험입니다.
  환은 몸통에 끼지 않고 손 옆에 배치합니다. 배에서 운반하는 동작 대신 초기 배치와 전달 신호를 입력합니다.
  `--no-grab`은 사람은 그대로인 채 구명환만 로프에 끌려가는 비교입니다.
- 물 통합 시험은 Water(include_boat=False, floating_bodies=[human, lifebuoy])로 두 독립 부력 대상을 지정합니다.
  선체 포함 기본값 True와 기존 부력 계약은 유지합니다. 이 시험은 연결 안정성이며 인체 부유 성능 검증은 아닙니다.
- 검증: 초기 분리·비침투·질량, 미수령 시 사람 가속도 0/환 가속도 발생, 전달 신호·거리·선속도·각속도 거부,
  회전된 수령 자세의 무점프 연결, 수령 후 사람으로 힘 전달, 놓은 뒤 추가 직접 견인력 제거와 관성 유지,
  오른손 수령, 제약 리셋과 부력·저항 아래 안정성을 확인합니다.

## 양팔을 곧게 펴서 구명환 착용 (2026-11-13)

- `view_wear`는 배와 분리된 중력 0 시험입니다. 로프는 처음부터 구명환에 연결되어 있습니다.
- Human(articulated_arms=True)은 좌우 각각 어깨 3·팔꿈치 1·손목 3 hinge를 생성합니다.
  이 모드의 팔꿈치 0도 형상은 실제 위팔·아래팔이 일직선입니다. 고정 팔 모드의 형상은 유지합니다.
  팔 질량을 분배해 인체 총질량 70kg을 유지하며, 관절 범위와 팔꿈치 역꺾임 제한을 적용합니다.
- actuator prefix는 HUMAN_ARM_ACTUATOR_PREFIX입니다. 시험 토크는 어깨·팔꿈치 ±40N·m,
  손목 ±22N·m입니다. 내부 힘을 ForceAccumulator에 중복 추가하지 않습니다.
- SelfWear는 WAITING → ALIGN_ARMS → INSERT_BOTH → WORN을 제어합니다.
  `start(data, delivery_ready=True)` 뒤 양어깨를 함께 회전하며 팔꿈치·손목 목표는 계속 0도입니다.
  목표 관절 각도 변화는 50Hz에서 회당 최대 0.025rad입니다. 실제 qpos/qvel은 덮어쓰지 않습니다.
- 양팔 정렬을 확인한 뒤 접근 진행률 `progress`(0..1)를 출력합니다.
  시연의 WearApproachFixture는 이 진행률에 따라 사람을 앞으로 이동시키고 환의 전달 위치를 지지합니다.
  실제 이동은 제한된 외력·토크와 물리 적분으로 계산합니다. 이는 접근 시험 장치이며 배 제어·수영 모델이 아닙니다.
  실제 통합에서는 전달부/사람 이동 제어로 이 장치를 대체해야 합니다.
- 이 경로는 손 잡기 weld를 사용하지 않습니다. HumanGrasp의 기존 잡기 인터페이스는 다른 시험용으로 유지합니다.
  양팔은 환 구멍을 동시에 통과하며, 몸통에 도달한 실제 상대 자세를 캡처해 착용 지지 weld를 켭니다.
  중심 오차 < 0.015m, 축 오차 < 0.03rad, 실제 양팔 각도 오차 < 0.025rad 조건을 확인합니다.
- ready_to_tow는 WORN과 몸통 지지가 유효할 때만 True입니다. WORN에서는 접근 장치의 모든 힘·토크를 해제해
  로프 견인으로 자유롭게 움직입니다. 팔은 완료 뒤에도 곧게 뻗은 상태를 유지합니다.
- ring_contact/human_contact는 인체 비트1·환 비트2로 접촉을 켭니다. 기본 비활성 값과 공유 Groups는 유지합니다.
  자기 몸 부위 간 접촉은 미구현입니다. 몸통 지지는 실제 겨드랑이 접촉·마찰 대신 weld로 근사합니다.
- 검증: 질량·14개 actuator·토크 제한, 실제 위팔/아래팔 직선성, 양손 동시 통과와 좌우 대칭,
  관절 범위·목표 각도 속도, 실제 pose/velocity 직접 변경 없음, 머리·소재 관통 없음,
  착용 후 접근 지지 해제·로프 견인, 전달 신호 거부와 리셋 복원을 확인합니다.
- 해부학적 관절 범위·근력·수상 착용과 임의 초기 자세의 충돌 회피는 검증하지 않았습니다.

## 시연과 시험 장면의 분리

- 잡기·착용의 조립/진행/초기화와 시험용 외력 장치는 `sim/scenarios.py`에 둡니다.
  `view_grasp.py`·`view_wear.py`는 CLI와 표시를 담당하고 테스트는 scenarios의 장면을 직접 사용합니다.
- `world.advance_world(world)`는 forward → acc.reset → 각 part.add_forces → acc.apply → step → forward를 실행합니다.
  제어 갱신·반복 리셋은 호출 측의 책임입니다. 기존 PhaseManager/Watchdog의 단계별 검사 순서는 유지합니다.
- `rope_visual.draw_rope`는 물리 상태를 변경하지 않고 현재 장력을 이용해 로프를 표시합니다.
  `clear=True`면 기존 표시를 비우며, 미연결 로프는 표시하지 않습니다.
