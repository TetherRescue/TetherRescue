# 철썩 효과 시험 맵 (조사 1)

파도가 지형(바위·해안)에 부딪힐 때 흰 물보라·거품이 이는 **화면 전용 효과**를 시험하고 렉을 재는 도구입니다.
MuJoCo에는 물을 입자로 계산하는 기능(SPH)이 없어서, 물리 대신 화면에 그림만 덧그립니다.
([MuJoCo 유체 모델 문서](https://mujoco.readthedocs.io/en/stable/computation/fluid.html): 물체에 걸리는 유체 저항만 있음)

담당: 미현 (물)

## 실행

저장소 루트에서, 가상환경을 켠 상태로 실행합니다.

```powershell
# 하나개 크기 맵 + 배 (추천)
python tools/splash_lab/hanagae_lab.py --robot --throttle 0.6

# 같은 장면, 효과 끔 (렉 비교)
python tools/splash_lab/hanagae_lab.py --robot --throttle 0.6 --mode off

# 작은 시험 맵 (20 x 10 m, 바위 1개 + 경사 모래사장)
python tools/splash_lab/splash_lab.py --mode fx --fx spray+foamtex+bulge --robot --throttle 0.6
```

### 조작

| 키 | 동작 |
| --- | --- |
| ↑ ↓ | 전진·후진 명령 ±0.1 |
| ← → | 조향 ±0.2 (누르면 자동조종 꺼짐) |
| A | 자동조종 다시 켬 (첫 번째 바위를 향함) |
| 스페이스 | 멈춤 |
| 마우스 | 왼쪽 드래그 회전 · 오른쪽 드래그 이동 · 휠 확대 |

터미널에 2초마다 `[렉]` 줄이 찍힙니다 (프레임당 물리+효과·메시·효과 그리기·화면 전송 시간, 실제 fps).
계산이 화면 속도(60 fps)를 못 따라가면 **시뮬 시간이 실제보다 느리게 흐릅니다** (파도·배가 슬로모션처럼 보임).

### 주요 옵션 (`hanagae_lab.py`)

| 옵션 | 설명 |
| --- | --- |
| `--mode off` | 효과 끔 |
| `--fx spray+foamtex+bulge` | 켤 효과 (기본값). `spray` 물보라 조각 · `foamtex` 거품 그림 · `bulge` 부딪힌 곳 수면 솟음 |
| `--sea three\|team\|regular\|irregular` | 파도 종류. `team` = 본 시뮬 `WAVES_DEFAULT` |
| `--mesh-grid 0.5` | 수면 메시 격자 [m] (기본 0.25, 본 시뮬은 0.5) |
| `--full` | 배 주변 50 m 패치 대신 바다 전체 계산 (렉 비교용, 무거움) |
| `--no-drag-fix` | 물 저항 수정 끄기 (아래 참고) |

## 맵

- **하나개 맵 치수** (`sim/world/coast_map.py`): 바다 260 x 160 m, 갯벌 25 m, 해안선 수직 턱 0.4 m, 모래사장 12 m, 육지
- **본 맵과 다른 점**
  - 철썩 시험용 **바위 3개** 추가 (본 맵에는 없음)
  - 바다 바닥을 −0.4 m → −1.0 m(갯벌 −0.7 m)로 낮춤. 바위 앞 반사파의 골이 바닥보다 내려가면 "마른 땅"으로 판정돼 가짜 철썩이 생기기 때문
  - 지형이 모두 충돌체 (배가 바위·해안에 부딪힘)
- **파도**: 사인파 3개(너울·풍랑·잔물결) + 바위·해안 턱 반사파 + 바위 뒤 그늘
- **물 표시**: 본 시뮬처럼 배 주변 50 m 패치만 촘촘히 계산하고 배를 따라 5 m 단위로 옮김. 바깥은 평평한 바다

## 팀 코드에 미치는 영향

**팀 코드 파일은 바꾸지 않습니다.** 실행 중인 프로세스 안에서만 다음을 바꿔 끼웁니다.

- `sim.water.water.wave_height` → 이 맵의 바다 (반사파·그늘 포함)
- `sim.water.water.water_drag` → 물 저항을 정지한 물이 아니라 "그 자리 물 입자 속도(파도 궤도 속도)"에 대해 계산하는 버전.
  `--no-drag-fix` 로 지금 물 모듈 그대로 쓸 수 있음.
  - 파도 속 표류 문제(추력 0 인 배가 파도를 거슬러 밀림, 예전 10초에 약 −6 m)는 main 의 `heave_world_only` 수정(2026-11-24)으로
    이미 해결됨. 지금 물 모듈로 재 보면 추력 0, 10초 표류: 본 시뮬 파도 +0.08 m · 파도 3개 +0.23 m
    (이 버전은 +0.02 m · −0.19 m). 둘 다 작아서 어느 쪽으로 돌려도 결과는 거의 같음

## 렉 측정 결과 (하나개 크기, 배 포함, 1280x720)

`python tools/splash_lab/hanagae_bench.py 결과.md` 로 다시 잴 수 있습니다. 단위 ms/프레임, 60 fps 예산 16.7 ms.
해안 턱 50 m 전체가 철썩이는 거의 최악의 장면 기준입니다.

| 패치 50 m · 메시 0.25 m | 효과 끔 | 효과 켬 | 효과만 |
| --- | --- | --- | --- |
| CPU (물리 · 효과 계산 · 메시 · 그리기 목록) | 13.9 | 31.3 | **+17.4** |
| GPU (메시 업로드 · 렌더) | 8.5 | 20.7 | **+12.2** |
| 프레임 / fps | 22.4 / 45 | 52.0 / 19 | |

- 남은 효과 비용은 대부분 **화면에 그리는 조각 수**(약 700개, 대부분 거품 그림)에 비례합니다.
  `hanagae_lab.py` 의 `FOAM_MAX`(거품 그림 상한, 기본 500)를 낮추면 더 가벼워집니다.
- 바다 전체를 계산(`--full`)하면 효과를 꺼도 메시 계산만 40 ms 이상이라 패치 방식이 맞습니다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `hanagae_lab.py` | 하나개 크기 맵, 물 패치, 최적화(감지 범위·거품 묶음·진폭 격자) |
| `splash_lab.py` | 작은 시험 맵 + 파도(반사·그늘·해안 감쇠)·효과·로봇 연결 코드 |

| `hanagae_bench.py` | 렉 측정 스크립트 |
